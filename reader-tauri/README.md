# EPUB Reader Tauri 1.2.0

Tauri 2 桌面端复用 EPUB-READER 的 Vue 书架、设置、登录、云端存储、后台管理和 EPUB.js 阅读页。书架与阅读器使用独立窗口。Windows 使用 WebView2。

## 数据与服务

Windows 客户端共享原书库 `%APPDATA%/epub-reader/db/epub_reader.db` 及同目录下的 `upload`。原书籍、分类、阅读进度、书签和批注可直接使用。空库会自动初始化。删除、改分类和保存阅读位置会更新共享数据。Tauri 使用独立的 WebView 登录会话，首次进入云端功能时需登录。

云端接口沿用 Electron 的地址 `http://localhost:8080`，由工作区的 bookstore Spring Boot 服务提供。Windows 安装包只包含桌面客户端。使用云端功能前，需运行已配置数据库的 bookstore 服务。

| 功能 | 客户端和服务端的交互 |
| --- | --- |
| 登录 | 获取验证码图片和 X-Captcha-Id，提交账号、密码和验证码，保存服务端返回的 Bearer 会话 |
| 书库 | 多选 EPUB 导入、元数据和封面提取、按文件哈希去重、分类增删改与分配、删除、导出 EPUB 和文本笔记 |
| 阅读 | 独立窗口、目录、翻页与滚动模式、搜索、排版与主题、恢复进度、书签和批注 |
| 云端 | 分类同步、multipart 上传、书单和配额、下载与阅读、删除、阅读进度回写。同步进度前用文件哈希匹配服务端书籍 ID |
| 管理 | 用户和书籍列表、角色、会员、启停用户、删除用户和云端书籍、调整存储配额 |

原 Electron 界面的“摘抄”仅提示选中文字，“选择保存路径”仅返回所选目录。这两个入口沿用原版行为。书签和批注保存在本地数据库，导出笔记时包含两者。

## 构建

Windows 需安装 Node.js、Rust stable MSVC、Visual C++ 构建工具、Windows SDK 和 WebView2。

~~~powershell
npm ci
npm run tauri -- dev
~~~

生成 Windows x64 NSIS 安装包：

~~~powershell
npm run tauri -- build --bundles nsis
~~~

输出目录为 `src-tauri/target/release/bundle/nsis`。本次已验证 Windows 安装，并从安装版打开现有书库。本轮没有在 macOS 和 Linux 上构建或验收。

## Windows 验证

2026-11-19 在相同的 1200 × 800 CSS 像素视口下，对照当前 Electron 源码构建和 Tauri 安装版。两端暴露的桌面接口名、默认窗口内容尺寸、书名和按钮的实际中文字体均相同。书架、设置及阅读工具栏的受测控件字号和颜色相同。阅读工具栏和侧栏的受测位置及尺寸一致；原生滚动条占宽造成书架卡片横向相差 0.8 CSS 像素、设置区内容宽度相差 1.6 CSS 像素。六张对照截图保存在 `verification/windows`。

已验证现有 12 本书的书架、独立打开 EPUB、89 项目录及章节跳转。使用临时 EPUB 验证了多选文件入口、元数据、重复导入跳过、分类分配、书签、批注和导出。导出的 EPUB 与源文件逐字节相同，文本笔记包含测试书签和批注。

后端联调使用真实 bookstore Spring Boot 程序和独立的本地 MariaDB。默认服务地址的验证码图片已在 Tauri 登录表单中显示。自动化登录使用在隔离测试 JVM 中通过 CaptchaChallengeService 创建的一次性验证码样例，经过真实登录接口取得测试管理员会话。受保护接口在独立 WebView 测试配置中使用该会话。已验证上传、分类同步、云书单、配额、从云端下载后阅读，以及服务端按正确的书籍 ID 返回已保存的 CFI。管理员角色、会员、禁用、删除测试用户和测试书籍及修改配额均已通过服务端回读确认。没有使用正式账号进行人工验证码登录验收。后端现有四项测试全部通过。

| Windows x64 发布版 | 安装包字节数 | 五次书架启动耗时（毫秒） | 中位数 |
| --- | ---: | --- | ---: |
| Electron 1.1.3 | 92,554,161 | 697、692、705、647、690 | 692 ms |
| Tauri 1.2.0 | 3,140,930 | 738、741、773、706、737 | 738 ms |

两版交替启动，每次启动新进程，计时到显示 12 张书架卡片。操作系统缓存和 WebView2 已预热。Electron 使用现有 SQLite 书库的一致性快照，上传目录指向同一批书籍。此结果不包含首次安装 WebView2 的时间。

复测工具 `scripts/benchmark.py` 和 `scripts/compare_ui.py` 依赖 Python 与 websocket-client。前者接受运行时名称和发布版 exe 路径，可加 `--read` 验证章节跳转。后者依次接受 Electron 可执行文件、已构建的 Electron 应用目录和 Tauri 可执行文件。可用 READER_BENCH_PROFILE 指定包含书库快照的 Electron 测试配置，READER_TEST_TITLE 指定阅读样本，READER_UI_EVIDENCE 指定截图目录。阅读测试会更新样本书的阅读位置。

## 文件与会话回归检查

本轮审查修复了导入失败遗留 EPUB 和封面、导出失败可能覆盖原文件、并发重新导入与文件清理冲突、旧库单本文件读取失败中断启动，以及过期请求影响新登录会话的问题。待清理路径和删除书库记录在同一 SQLite 事务中提交；文件被占用时保留清理任务，下次启动或彻底删除操作会重试。导出通过目标目录内临时文件完成后再替换。

Windows 发布版已验证真实文件导入、重复检测、分类分配、书签批注、EPUB 和笔记导出、模拟 SQLite 写入失败时两份文件均回滚，以及彻底删除测试书。Rust 清理测试覆盖共享、已缺失和暂时无法删除的文件。会话测试覆盖管理员接口拒绝访问、旧请求迟到以及当前会话失效。本轮未重新执行真实后端端到端或其他操作系统的测试。
