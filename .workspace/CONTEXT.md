# Workspace context contract

更新时间：2026-11-23

本目录是跨电脑、跨智能体的唯一上下文来源，必须随工作空间 Git 仓库提交。任何智能体不得把关键项目事实只留在聊天记录中。

## 必须入库的信息

- 项目清单、路径、类型、版本和构建/启动命令
- 服务器、端口、服务归属、环境、部署方式和验证证据
- 数据库引擎、实例、库名、迁移状态、备份位置和连接方式
- 定时任务、触发器、脚本、最近运行时间和结果
- 当前目标、已完成、未完成、验证证据、阻塞和下一步
- Git 分支、提交 SHA、远端、CI、部署和真实设备/支付验收边界

## 敏感信息

敏感信息也必须有仓库记录，但以加密文件入库：`infrastructure/secrets.enc.json`。明文密码、Token、私钥不得提交。解密密钥只放在每台电脑的系统凭据管理器或外部密钥文件中，仓库记录 `keyRef`、加密算法、版本和恢复步骤。没有解密密钥时，其他电脑仍能读取完整拓扑和上下文，只不能执行需要凭据的操作。

## 智能体工作协议

1. 开始任务前读取 `workspace.json`、本文件、对应项目文件、基础设施文件和最近快照。
2. 开始任务后先记录目标、分支、SHA 和当前状态。
3. 结束任务前更新上下文、证据和下一步，并生成快照。
4. 服务器、数据库或定时任务变更必须同时更新对应 JSON 和变更记录。
5. 清理默认报告模式；删除前必须经过白名单、保留期、进程占用和 dry-run 检查。
